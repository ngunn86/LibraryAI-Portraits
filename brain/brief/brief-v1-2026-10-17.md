# The portraits tool: a brief to start from

For the chat that builds the portraits tool (2026-10-17). The tool is a standalone app in its own repo, and it is also the first project the autonomous build harness runs end to end (Library-AI's readiness gate G10). The full requirements are the `tool`-tagged lines in `brain/spec/portraits.md` of the Library-AI---Rev1 repo (PORT-001 to PORT-022, PORT-040, PORT-070 to PORT-081, PORT-091); the hand-off into the library is PORT-090 and API-063, with the contract `brain/contracts/portraits.manifest.schema.json` and its sample. Attach those three files to the chat with this brief.

## What it does

For every teacher in the library who has no portrait, find a public-domain or openly licensed photograph that certainly shows them, make a stylized portrait in the owner's halftone style, check it, and deliver it to the library with its rights record, where an admin approves it. The owner's three hand-made portraits in `design/portraits/` are the target; the tool's job is to match them, by code, for a few hundred teachers.

## The style (fixed; the owner's)

- A one-colour halftone of the photo: round white dots on a 45° grid, about 110 dots across the square, dark tones left transparent so the page's colour shows through as the shadows; contrast lifted a little so the face reads in dots.
- One thin, smooth white outline just outside the head and shoulders, following the hair's overall shape.
- A square crop, head and shoulders, the head near the top, the face filling most of the width, the shoulders running off the bottom; no background at all.
- The likeness is the photo's own: the dots are made by code from its tones, never by an image model; the image model draws only the outline line, which code extracts and lays over the dots.
- One set of settings for every teacher, recorded with each portrait (`recipe_version`, `settings`).
- Output: a 1,000 by 1,000 PNG master, pure white on transparency.

## Where originals come from (fixed; rights)

- Wikimedia Commons and the Library of Congress only. Public domain first (public domain, CC0, the Library of Congress's "no known restrictions"), then CC BY and CC BY-SA; nothing else, ever (no NC, ND, fair use or unknown rights).
- A certain match only, in this order: the image on the teacher's Wikidata record (P18); Commons files whose structured data says they depict the teacher's Wikidata item (P180); Library of Congress prints and photographs whose record names the teacher with matching dates. A file merely in a Commons category, or matched by name alone, never counts.
- Every original's record is kept: source, source id, page and file links, title, author and date as given, licence and its link, credit line, how it was matched, size and checksum.

## The pipeline, per teacher

1. Choose the best candidate original not yet set aside: public domain first, then the clearest and largest.
2. Check the original with a vision model: one person, the face fully in view and large enough, not badly damaged. A group photo, a tiny or ruined original is set aside before anything is spent.
3. Cut-out: a background-removal model (Bria RMBG 2.0 or the like; a direct fal key if OpenRouter has none). Keep the cut-out for later tries.
4. Crop, by code. 5. Descreen, by code: detect a printed dot pattern by frequency analysis, filter it, edge-preserving blur, restore contrast; skip when there is none.
6. Halftone, by code, straight onto transparency.
7. Outline: an image model (starting setting Gemini 3 Pro Image; challengers GPT Image 2 and FLUX.2 Pro) draws one white contour around the cut-out on black; code keeps only the line.
8. Check the draft with a vision model of a different family than the outline model: outline hugs the figure, cut-out clean, no moiré, face reads and matches the original, crop matches the examples. A failing draft is remade; a passing one is delivered.
9. Failures: two failures set an original aside; a turn-down in the library sets it aside at once; at most three originals per teacher; then the teacher keeps the blank portrait and the tool tries again on a later run when new candidates appear.

## The hand-off to the library

- The manifest (`portraits.manifest.schema.json`): one record per portrait with the teacher (by the library's person id, or name and dates), the master's file name and SHA-256, the original's source, link, title, creator, date, licence, licence link, credit and how it was matched, the attempt number, the check's notes, any originals set aside and why, and a `request_id` when the draft answers a request.
- Two ways in: a zip of masters plus `manifest.json` for the admin's bulk upload; or the API with a tool key: `GET /api/v2/teachers` (who needs a portrait), `GET /api/v2/portraits/requests` (the admin's Try again notes, "find another original" and pasted-link requests), `POST /api/v2/portraits` (one record plus its PNG, multipart). The library validates against the schema and answers with the queue item's id or the refused field.
- Nothing goes live from the tool: every portrait lands in the library's approval queue.

## Running and limits

- Runs on the owner's PC or any machine with its keys; each teacher is a resumable job in the tool's own queue; a run takes the library's requests first, then teachers without a portrait, and skips approved ones.
- Its own OpenRouter key and a spend cap, $250 for the first run (about 17 cents an attempt is the estimate; the first run for a few hundred teachers $100 to $200; the trial about $30). Stops at the cap. Logs spend per attempt.
- Settings file: the recipe settings, the three model names, the cap, the library's address and the tool key. Keys never in the repo.

## The trial, inside the first run

Before the first run over every teacher: the owner's three originals (targets: the hand-made portraits) plus about 20 found originals including scanned prints with a dot pattern, a tiny original, a group photo, an engraving and a damaged print; the three outline models each with the same cut-out and code; the check scores them, the best wins, the cheaper when close; a board of every result beside its original and the examples goes to the owner for a veto; nothing waits for the owner.

## Done when

- The sample manifest validates and imports to the library's queue; a record with no licence is refused naming the field.
- The owner's three examples are reproduced by the pipeline closely enough that the check passes them against the hand-made targets.
- The trial's board exists, the defaults are set from it, and one full harness run (plan, build, tests, digest, veto) has completed on this project.
- Nothing in the tool reads the library's reference shelf or its scans; originals come only from the two sources by the three match rules.

## Not in scope

The library's side (the queue item, the people screen, the credits page, the blank portrait) is Library-AI's build. The tool doesn't choose which teachers exist, doesn't edit the library's records, and never serves images to readers.
